# 刀片模式（Blade Mode）设计文档

## 背景

Whisper API 对单次请求的文件大小和推理时长有限制（假定约 100 秒/次）。当视频/音频远超此限制时，需要将其切分为多个短片段。

现有 Time Slicer 使用 brute-force 等时切片，切片之间需要 overlap 来保证语音不被截断，后续还需要 LLM 进行单字合并去重。Blade Mode 的目标是让人类操作员在 **看到音频波形和 VAD 语音活动区间** 的前提下手动选择切点，从而：

- 消除 overlap 及其带来的去重逻辑
- 在静默区间精确切片，不破坏任何词语

## 核心交互设计

### 1. 工具栏

每条 ASR 方法轨道（method lane）的控制面板上有两个按钮：

| 按钮 | 类型 | 行为 |
|------|------|------|
| ✂ 刀片按钮 | toggle（开/关） | 进入 / 退出刀片模式 |
| Send Slices | 单次触发 | 将当前确认的切点转为切片列表，发送到转录模块；若正在刀片模式中则自动退出 |

### 2. 刀片模式下的光标行为

切点必须为**整数秒**（受下游 slicer 数据结构限制）。

在波形区域内鼠标移动时，同时绘制两条竖线：

- **灰色虚线**：跟随鼠标横坐标（精确位置）
- **彩色竖线**：吸附到离光标最近的整秒位置

彩色竖线有两种视觉状态：

| 状态 | 外观 | 含义 |
|------|------|------|
| proposed（提议） | 减淡 / 半透明 | 鼠标悬停时的候选切点 |
| confirmed（确认） | 完整饱和度 | 已确认的切点，鼠标离开后仍保留 |

### 3. 切点的生命周期

```
None ──hover──▶ proposed ──click──▶ confirmed ──shift+click──▶ None
```

- **hover**：鼠标进入波形区域，proposed 线出现
- **click**（无 shift）：在最近整秒处添加一个 confirmed 切点
- **shift+click**：移除该位置的 confirmed 切点
- **leave**：鼠标离开波形区域，proposed 线和灰色跟随线消失；confirmed 线不受影响

### 4. "upcoming" 时长预览

刀片模式激活且鼠标在波形区域内时，波形图**左上角**显示一个灰底白字文本块：

```
upcoming: X min YY s
```

含义：从上一个 confirmed 切点（或 0）到当前吸附秒数之间的距离，即"如果在这里切，这一段有多长"。帮助操作员判断是否超出 API 限制。

鼠标离开波形区域时文本块消失。

### 5. 非刀片模式下的行为保留

刀片模式关闭时，波形区域的鼠标交互恢复为原有的拖拽平移 + 滚轮/Alt+滚轮缩放，不受影响。

刀片模式开启时，左键点击被切点操作消费，不触发拖拽。滚轮平移和 Alt+滚轮缩放仍可用。

### 6. 切片结果的数据格式

confirmed 切点列表 `[c1, c2, c3]`（已排序的整秒数）加上总时长 `duration`，转换为：

```
[(0, c1), (c1, c2-c1), (c2, c3-c2), (c3, ceil(duration)-c3)]
```

即 `[(start_sec, duration_sec), ...]`，与现有 Time Slicer 的输出格式一致，可直接被转录模块消费。

### 7. 发送到转录模块

点击 "Send Slices" 后：

1. 将 confirmed 切点转为上述格式的切片列表
2. 连同当前媒体文件路径和总时长，推送到转录模块
3. 转录模块接收后**仅替换切片数据**，保留已有的转码/码率等设置
4. 若当前处于刀片模式，自动退出

## 设计决策备忘

- **整秒精度**：在 Premiere-like 的未来编辑器中可放宽为帧级精度，但当前受 slicer `(start, duration)` 的 int 约束
- **per-lane 独立性**：每条方法轨道各自维护切点列表，操作员可在不同 VAD 方法的波形上分别标记，比较后选择最优的一组发送
- **与自动切片的关系**：Blade Mode 是对 Time Slicer 自动切片的补充/替代，两者产出相同格式，转录模块不需区分来源
- **试验性定位**：当前实现寄生在 VAD 实验界面中。未来若构建 Premiere-like 时间轴编辑器，应将此交互作为内建工具（razor tool），直接操作统一的时间轴，而非附着在 per-method 轨道上
