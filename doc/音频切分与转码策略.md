# 音频切分与转码策略

## 概述

本文档详细说明了音频切分（time slicing）和转码（transcoding）的决策逻辑。

---

## 约束条件

1. **API 限制**: Whisper API 的文件大小限制为 25MB，我们保守地使用 15MB 作为目标大小（约60%）
2. **最优切片时长**: 10分钟（600秒）- 这是在减少API调用次数和避免超时之间的平衡点
3. **目标比特率**: 128kbps - 对于语音内容，这个比特率提供足够的质量

---

## 决策逻辑

### 第一步：计算原始比特率下的最大切片时长

```
max_duration_original = floor((15MB * 8) / audio_bitrate)
```

### 第二步：如果原始比特率 > 128kbps，计算转码后的最大切片时长

```
max_duration_transcoded = floor((15MB * 8) / 128kbps)
```

### 第三步：决定是否转码

转码条件（满足任一即转码）：
1. 转码后能达到目标时长（10分钟）
2. 转码后的切片时长显著长于原始（>1.5倍）

### 第四步：使用有效比特率计算最终切片

```
effective_bitrate = 128kbps (if transcode) else audio_bitrate
slice_duration = min(600s, max_duration)
```

## 示例计算

### 示例 1: 320kbps 音频（高比特率）

**不转码情况:**
- max_duration = floor((15728640 * 8) / 320000) = 393秒 ≈ 6.5分钟
- 文件大小 = 320kbps * 393s / 8 = 15.72MB

**转码到 128kbps:**
- max_duration = floor((15728640 * 8) / 128000) = 983秒 ≈ 16.4分钟
- 实际使用 min(600, 983) = 600秒 = 10分钟
- 文件大小 = 128kbps * 600s / 8 = 9.6MB

**决策:** ✅ 转码
- 原因: 转码后达到目标时长（600秒 >= 600秒）
- 收益: 切片时长从 6.5分钟增加到 10分钟（+53%），API调用次数减少约35%

### 示例 2: 128kbps 音频（目标比特率）

**不转码情况:**
- max_duration = floor((15728640 * 8) / 128000) = 983秒
- 实际使用 min(600, 983) = 600秒 = 10分钟
- 文件大小 = 128kbps * 600s / 8 = 9.6MB

**决策:** ❌ 不转码
- 原因: 原始比特率 <= 目标比特率，无需转码
- 已经能达到最优切片时长（10分钟）

### 示例 3: 96kbps 音频（低比特率）

**不转码情况:**
- max_duration = floor((15728640 * 8) / 96000) = 1311秒
- 实际使用 min(600, 1311) = 600秒 = 10分钟
- 文件大小 = 96kbps * 600s / 8 = 7.2MB

**决策:** ❌ 不转码
- 原因: 原始比特率 < 目标比特率，无需转码
- 已经能达到最优切片时长（10分钟）

### 示例 4: 160kbps 音频（中等比特率）

**不转码情况:**
- max_duration = floor((15728640 * 8) / 160000) = 786秒 ≈ 13.1分钟
- 实际使用 min(600, 786) = 600秒 = 10分钟

**转码到 128kbps:**
- max_duration = 983秒
- 实际使用 = 600秒

**决策:** ❌ 不转码
- 原因: 虽然原始比特率 > 128kbps，但不转码已能达到目标时长
- 转码后切片时长不变（都是600秒），无收益

## 转码实现细节

### FFmpeg 参数

```python
if should_transcode:
    output_options['acodec'] = 'aac' if output_ext == '.m4a' else 'libmp3lame'
    output_options['b:a'] = str(target_bitrate)  # '128000'
```

### 输出格式选择
- `.m4a` 文件：使用 AAC 编码器
- `.mp3` 文件：使用 LAME MP3 编码器

### 与其他功能的兼容性
- ✅ 与音频扰动（perturbation）功能兼容
- ✅ 与文件名清理功能兼容
- ✅ 与并发转录功能兼容

## 性能考虑

### 转码开销
- 转码会增加处理时间（取决于音频长度和硬件性能）
- 典型情况下，转码10分钟音频需要几秒到几十秒

### 收益
- 减少API调用次数
- 减少网络传输数据量
- 可能减少总体处理时间（更少的API往返）

### 何时收益最大
- 原始比特率很高（>256kbps）
- 音频总时长很长（>1小时）
- 网络环境不佳时

## 配置选项

- 在配置文件中添加 `target_transcode_bitrate` 选项
- 根据音频类型（语音 vs 音乐）使用不同的目标比特率
- 提供 GUI 选项让用户选择转码策略

---

## 总结

这个转码策略的核心思想是：
1. **优先保证切片时长**: 更长的切片意味着更少的API调用
2. **仅在有收益时转码**: 避免不必要的处理开销
3. **自动化决策**: 减轻用户负担
4. **保守策略**: 使用 15MB 而非 25MB 限制，确保稳定性
